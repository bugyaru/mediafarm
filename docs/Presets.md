# 📖 Документация по формированию пресетов в MediaFarm

Пресет в MediaFarm — это декларативная JSON-спецификация, описывающая конвейер (pipeline) обработки медиафайла. Пресет определяет, какие шаги будут выполнены, какие движки (ffmpeg, ffmbc, yt-dlp) использованы, какие кодеки и параметры масштабирования применены, а также куда будет сохранен результат.

## 1. Корневая структура пресета (`PresetSpec`)

Это объект верхнего уровня, который вы передаете в UI или API.

| Поле | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `name` | `string` | **Обязательно** | Уникальное имя пресета (например, `proxy_1080p_nvenc`). |
| `version` | `integer` | `1` | Версия пресета. Позволяет хранить историю изменений. |
| `description` | `string` | `null` | Человеко-читаемое описание назначения пресета. |
| `selector` | `object` | `{}` | Словарь меток для планировщика задач (например, `{"gpu": "nvidia"}`). |
| `requires_gpu` | `boolean` | `false` | Требует ли выполнение этого пресета наличия GPU. |
| `gpu_sessions` | `integer` | `1` | Сколько GPU-сессий (слотов) занимает одна задача этого пресета. |
| `cpu_cost` | `integer` | `1` | Сколько CPU-слотов резервируется под задачу. |
| `max_attempts` | `integer` | `3` | Максимальное количество автоматических повторных попыток при сбое. |
| `timeout_s` | `integer` | `null` | Глобальный таймаут выполнения всей задачи в секундах. |
| `steps` | `array` | **Обязательно** | Массив объектов, описывающих последовательность шагов обработки. |

---

## 2. Структура шага (`StepSpec`)

Каждый элемент массива `steps` описывает конкретную операцию.

| Поле | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `id` | `string` | **Обязательно** | Идентификатор шага. Допустимые значения: `acquire`, `probe`, `transcode`, `thumbnail`, `verify`, `publish`, `notify`. |
| `engine` | `string` | `null` | Движок обработки: `ffmpeg`, `ffmbc`, `ytdlp`, `python`. |
| `hwaccel` | `string` | `"auto"` | Аппаратное ускорение: `"auto"`, `"cuda"`, `"cpu"`. |
| `fallback_to_cpu`| `boolean` | `true` | Если `true`, при сбое GPU-кодирования задача автоматически перезапустится на CPU. |
| `mode` | `string` | `"staged"` | Режим выполнения: `"staged"` (поэтапно с сохранением во временное хранилище) или `"stream"` (потоковая обработка). |
| `resume` | `boolean` | `true` | Поддержка докачки неполных файлов (актуально для `acquire`). |
| `video` | `object` | `null` | Спецификация видеокодирования (`VideoSpec`). Обязательна для шага `transcode`. |
| `audio` | `array` | `[]` | Массив спецификаций аудиокодирования (`AudioSpec`). |
| `scale` | `object` | `null` | Спецификация изменения разрешения (`ScaleSpec`). |
| `deinterlace` | `string` | `"auto"` | Деинтерлейсинг: `"off"`, `"auto"`, `"force"`. |
| `container` | `string` | `null` | Целевой контейнер: `"mp4"`, `"mkv"`, `"mxf"`, `"ts"` и т.д. |
| `extra_in` | `array` | `[]` | Дополнительные аргументы командной строки **до** входного файла (`-i`). |
| `extra_out` | `array` | `[]` | Дополнительные аргументы командной строки **после** входного файла. |
| `checks` | `array` | `[]` | Массив строк-проверок для шага `verify` (см. раздел 4). |
| `storage` | `string` | `null` | Имя хранилища (Storage), куда сохранять результат. **Обязательно для `publish`**. |
| `path` | `string` | `null` | Шаблон пути сохранения. Поддерживает переменные: `{yyyy}`, `{mm}`, `{dd}`, `{asset.stem}`, `{asset.name}`, `{ts}`. **Обязательно для `publish`**. |
| `on_conflict` | `string` | `"skip"` | Действие при существовании файла: `"skip"` (пропустить), `"overwrite"` (перезаписать), `"version"` (добавить суффикс версии). |
| `at` | `array` | `[]` | Временные метки для извлечения кадров (например, `["10%", "50%", "00:01:30"]`). Используется в шаге `thumbnail`. |

> ⚠️ **Важно:** Объект `StepSpec` имеет `extra="allow"`, что означает, что вы можете передавать в него произвольные поля, специфичные для конкретного движка (например, `live: true` для `ytdlp` или `profile: "imx50"` для `ffmbc`).

## 3. Спецификации медиапараметров

### 3.1. Видео (`VideoSpec`)
| Поле | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `codec` | `string` | `"h264_nvenc"` | Целевой видеокодек (например, `h264_nvenc`, `libx264`, `hevc_nvenc`, `av1_nvenc`, `mpeg2video`). |
| `cpu_codec` | `string` | `"libx264"` | Запасной кодек для CPU, если `fallback_to_cpu` сработает. |
| `rc` | `string` | `"vbr"` | Режим контроля битрейта: `"vbr"`, `"cbr"`, `"cq"`, `"constqp"`. |
| `bitrate` | `string` | `"6M"` | Целевой битрейт (например, `"6M"`, `"1500k"`). |
| `maxrate` | `string` | `null` | Максимальный битрейт (для VBR). |
| `bufsize` | `string` | `null` | Размер буфера_rate control (например, `"12M"`). |
| `cq` | `integer` | `null` | Constant Quality (например, `23` для libx264). |
| `preset` | `string` | `"p5"` | Пресет скорости кодирования (для NVENC: `p1`...`p7`, для CPU: `ultrafast`...`veryslow`). |
| `profile` | `string` | `null` | Профиль кодека (например, `"high"`, `"main"`). |
| `gop` | `integer` | `50` | Размер группы кадров (GOP). |
| `bframes` | `integer` | `2` | Количество B-кадров. |
| `pix_fmt` | `string` | `"yuv420p"`| Формат пикселей (например, `yuv420p`, `yuv422p`, `yuv444p`). |
| `copy` | `boolean` | `false` | Если `true`, видеопоток копируется без перекодирования (`-c:v copy`). |

### 3.2. Аудио (`AudioSpec`)
Можно указать несколько потоков (например, для создания дорожек с разным битрейтом).
| Поле | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `codec` | `string` | `"aac"` | Аудиокодек (`aac`, `libopus`, `mp3`, `pcm_s16le`). |
| `bitrate` | `string` | `"192k"` | Аудиобитрейт. |
| `channels` | `integer` | `2` | Количество каналов. |
| `sample_rate`| `integer` | `48000` | Частота дискретизации в Гц. |
| `loudnorm` | `string` | `"off"` | Нормализация громкости: `"off"` или `"ebu_r128"`. |
| `copy` | `boolean` | `false` | Копировать аудиопоток без перекодирования. |
| `map` | `string` | `"0:a?"` | FFmpeg map-правило для выбора потока. |

### 3.3. Масштабирование (`ScaleSpec`)
| Поле | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `width` | `integer` | `null` | Целевая ширина. |
| `height` | `integer` | `null` | Целевая высота. |
| `mode` | `string` | `"fit"` | Режим: `"fit"` (вписать с сохранением пропорций), `"fill"` (заполнить, обрезая края), `"exact"` (точное растяжение). |
| `keep_aspect`| `boolean` | `true` | Сохранять ли соотношение сторон (добавляет паддинги при `mode: "fit"`). |
| `hw` | `string` | `"auto"` | Где выполнять масштабирование: `"auto"`, `"cuda"`, `"cpu"`. |

> ⚠️ **Валидация:** В `ScaleSpec` обязательно должен быть указан хотя бы один параметр: `width` или `height`.

## 4. Система проверок (`checks` в шаге `verify`)

Шаг `verify` анализирует результат и может отклонить задачу, если файл не соответствует критериям. Поддерживаемые строки проверок:
- `"has_video"`: Файл содержит видеопоток.
- `"has_audio"`: Файл содержит аудиопоток.
- `"duration_delta<=1.0"`: Разница длительности исходного и выходного файла не превышает 1.0 секунды.
- `"size>1024"`: Размер выходного файла больше 1024 байт (защита от пустых файлов).
- `"height==608"`: Точная проверка высоты кадра (полезно для PAL/SD-форматов с активными строками, как в IMX50).

---

## 5. Строгие правила валидации (`validate_spec`)

Система отклонит сохранение пресета, если нарушены следующие правила:
1. **Уникальность шагов:** Все `id` в массиве `steps` должны быть уникальны.
2. **Допустимые ID:** `id` должен быть строго одним из: `acquire`, `probe`, `transcode`, `thumbnail`, `verify`, `publish`, `notify`.
3. **Обязательный видео-блок:** Если присутствует шаг `transcode`, в нем **обязательно** должен быть объект `video`.
4. **Обязательная публикация:** Если присутствует шаг `publish`, в нем **обязательно** должны быть заполнены поля `storage` и `path`.
5. **Логика GPU:** Если в пресете используются только движки, не поддерживающие CUDA (например, `ffmbc` или `ytdlp`), система автоматически установит `requires_gpu: false` и удалит `gpu` из `selector`, даже если вы указали их вручную.
6. **Селектор GPU:** Если `requires_gpu: true`, система автоматически добавит `{"gpu": "nvidia"}` в `selector`.

## 6. Примеры готовых пресетов (из `BUILTIN_PRESETS`)

### Пример 1: Классический прокси-транскодинг с GPU и откатом на CPU
```json
{
  "name": "proxy_1080p_nvenc",
  "version": 1,
  "requires_gpu": true,
  "gpu_sessions": 1,
  "cpu_cost": 2,
  "description": "H.264 1080p на NVENC, fallback на CPU при необходимости",
  "steps": [
    {
      "id": "acquire",
      "mode": "staged",
      "resume": true
    },
    {
      "id": "probe",
      "engine": "ffmpeg"
    },
    {
      "id": "transcode",
      "engine": "ffmpeg",
      "hwaccel": "auto",
      "fallback_to_cpu": true,
      "deinterlace": "auto",
      "video": {
        "codec": "h264_nvenc",
        "cpu_codec": "libx264",
        "rc": "vbr",
        "bitrate": "6M",
        "maxrate": "8M",
        "bufsize": "12M",
        "preset": "p5",
        "profile": "high",
        "gop": 50,
        "bframes": 2
      },
      "scale": {
        "height": 1080,
        "mode": "fit"
      },
      "audio": [
        {
          "codec": "aac",
          "bitrate": "192k",
          "channels": 2
        }
      ],
      "container": "mp4",
      "extra_out": ["-movflags", "+faststart"]
    },
    {
      "id": "thumbnail",
      "engine": "ffmpeg",
      "at": ["10%", "50%"]
    },
    {
      "id": "verify",
      "checks": ["has_video", "has_audio", "duration_delta<=1.0", "size>1024"]
    },
    {
      "id": "publish",
      "storage": "out",
      "path": "{yyyy}/{mm}/{asset.stem}_1080p.mp4",
      "on_conflict": "skip"
    }
  ]
}
```

## 7. Динамическое переопределение (Overrides)

MediaFarm поддерживает механизм `overrides`, позволяющий изменять параметры пресета "на лету" при создании задачи, не создавая новый пресет. Это работает через глубокое слияние (deep merge).

**Пример:** У вас есть базовый пресет `proxy_1080p_nvenc`, но для конкретной задачи вы хотите изменить битрейт на `10M` и отключить звук.

При создании задачи (в `params` или через API) вы передаете:
```json
{
  "preset_name": "proxy_1080p_nvenc",
  "overrides": {
    "transcode": {
      "video": {
        "bitrate": "10M"
      },
      "audio": []
    }
  }
}
```
Система применит эти изменения к спецификации перед запуском конвейера.

## 8. Рекомендации и лучшие практики

1. **Всегда используйте `fallback_to_cpu: true`** для продакшн-пресетов с `h264_nvenc`/`hevc_nvenc`. Это гарантирует, что задача не "застрянет" навсегда, если все GPU-слоты заняты или драйвер NVIDIA временно недоступен.
2. **Добавляйте `"-movflags", "+faststart"`** в `extra_out` для контейнера `mp4`. Это перемещает moov-атом в начало файла, позволяя начинать воспроизведение в браузере до полной загрузки файла.
3. **Используйте шаг `verify`**. Проверки `duration_delta` и `size` защищают от сохранения битых или пустых файлов в целевое хранилище.
4. **Проверяйте через UI**. Перед сохранением нового пресета используйте кнопку **"Проверить"** в интерфейсе MediaFarm. Она запустит `validate_spec` и покажет точные ошибки валидации без сохранения мусора в базу данных.
5. **Шаблонизация путей**. В поле `path` шага `publish` активно используйте переменные: `{asset.stem}` (имя файла без расширения), `{yyyy}`, `{mm}`, `{dd}` для автоматического создания структурированных директорий.

Если вам нужно добавить собственный встроенный пресет в код, его следует добавить в словарь `BUILTIN_PRESETS` в файле `packages/mf-core/mf_core/media/presets.py`, после чего он станет доступен через кнопку "Загрузить встроенные" в UI.
